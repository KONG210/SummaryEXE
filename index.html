Architecture vs Organization

★ เน้นเนื้อหา
  • Architecture (WHAT) คือสิ่งที่โปรแกรมเมอร์ “มองเห็น” เช่น instruction set, addressing mode, data type
  • Organization (HOW) คือการสร้างให้เกิดจริงในระดับฮาร์ดแวร์ เช่น cache, pipeline, bus width, clock speed (เป็นเรื่องของวิศวกรฮาร์ดแวร์)
วิธีจำ: ถ้าเปลี่ยนแล้วโปรแกรมต้องเขียนใหม่ = Architecture · ถ้าแค่เร็วขึ้นช้าลง = Organization

Classes of Computers

★ เน้นเนื้อหา
  • Supercomputer: งานคำนวณวิทยาศาสตร์และวิศวกรรมระดับสูง ความสามารถสูงสุด แต่มีส่วนแบ่งตลาดน้อยมาก
  • Embedded: ซ่อนเป็นชิ้นส่วนในระบบอื่น มีข้อจำกัดเข้มงวดด้าน power, performance และ cost (มักเป็นงาน real-time)

Components & Inside the CPU

★ เน้นเนื้อหา

อุปกรณ์หลัก: Input · CPU · Memory (RAM) · Storage · Motherboard · Output · PSU · GPU

  1. Control Unit ควบคุมการทำงานของ CPU
  2. ALU ประมวลผลข้อมูล (คณิตศาสตร์และตรรกะ)
  3. Registers เป็นที่เก็บข้อมูลภายใน CPU (PC, IR, status/flags)
  4. CPU interconnection เชื่อม CU, ALU และ register เข้าด้วยกัน

Machine Cycle (4 ขั้น)

★ เน้นเนื้อหา
  1. Fetch: ดึงคำสั่งจาก memory
  2. Decode: Control Unit แปลคำสั่ง
  3. Execute: ALU ทำงานตามคำสั่ง
  4. Store: เขียนผลกลับลง memory แล้ววนกลับไปข้อ 1

CPU Time / CPI — สูตรต้องจำ

★ เน้นคำนวณ
CPU Time = Clock Cycles × Cycle Time = Clock Cycles ÷ Clock Rate
Clock Cycles = IC × CPI
CPU Time = IC × CPI × Cycle Time = (IC × CPI) ÷ Clock Rate
  • ความหมาย: IC = จำนวนคำสั่งที่โปรแกรมรัน · CPI = จำนวน clock เฉลี่ยที่ใช้ต่อ 1 คำสั่ง · Cycle time = ความยาวของ 1 clock (เช่น 250 ps) · Clock rate = จำนวน clock ต่อวินาที (เช่น 4 GHz) = 1 ÷ cycle time
  • IC ขึ้นกับ program, ISA และ compiler
  • CPI ขึ้นกับฮาร์ดแวร์ CPU และสัดส่วนคำสั่ง (instruction mix)
  • ทำให้เร็วขึ้นได้ 2 ทาง: ลดจำนวน clock cycles หรือเพิ่ม clock rate (สองอย่างนี้มักต้อง trade-off กัน)

ขั้นตอนทำโจทย์ “เครื่องไหนเร็วกว่า กี่เท่า”

  1. โจทย์: ISA เดียวกัน · A: cycle time 250 ps, CPI 2.0 · B: cycle time 500 ps, CPI 1.2 · ถามว่าเครื่องไหนเร็วกว่า และกี่เท่า
  2. เขียน CPU Time ของแต่ละเครื่อง = I × CPI × Cycle Time (ISA เดียวกัน จำนวนคำสั่งจึงเท่ากัน ใช้ I แทน)
  3. A: I × 2.0 × 250ps = 500ps·I · B: I × 1.2 × 500ps = 600ps·I
  4. เวลาน้อยกว่า = เร็วกว่า จึงได้ว่า A เร็วกว่า
  5. หาร ตัวช้า ÷ ตัวเร็ว: 600/500 = 1.2 แปลว่า A เร็วกว่า B 1.2 เท่า B มี CPI ต่ำกว่าก็จริง แต่ clock ช้ากว่า 2 เท่า สุดท้ายจึงแพ้

Performance

คำนวณ
  • Response time = เวลาทำงานหนึ่งชิ้นให้เสร็จ · Throughput = งานที่ทำได้ต่อหน่วยเวลา
  • Performance = 1 / Execution Time · “X เร็วกว่า Y n เท่า” แปลว่า PerfX/PerfY = TimeY/TimeX = n (เช่น 15s/10s = 1.5)
  • Elapsed time นับทุกอย่าง (I/O, OS, idle) · CPU time นับเฉพาะเวลาที่ CPU ทำงานให้โปรแกรมนั้น (user + system)
  • Clock period (cycle time) = 1/clock rate 4 GHz = นาฬิกาเดิน 4×10⁹ ครั้งต่อวินาที → 1 ครั้งยาว 1/(4×10⁹) s = 0.25 ns = 250 ps
CPU Time Example: A ใช้ 2 GHz และ 10 s ถ้าจะทำ B ให้เสร็จใน 6 s แต่ B ต้องใช้ cycles มากกว่า 1.2 เท่า
(1) cyclesA = 10 s × 2 GHz = 20×10⁹ (2) cyclesB = 1.2 × 20×10⁹ = 24×10⁹ (3) ClockB = 24×10⁹ ÷ 6 s = 4 GHz
แนวคิด: เวลา = cycles ÷ clock rate · B ต้องใช้ cycles มากขึ้นแต่อยากให้เสร็จเร็วขึ้น จึงต้องเร่ง clock เป็น 2 เท่า

Von Neumann vs Harvard

★ เน้นเนื้อหา
Von NeumannHarvard
Memoryเก็บ program และ data ร่วมกัน (stored-program)แยก memory และ bus ระหว่าง instruction กับ data
เด่นแบบดั้งเดิม พบบ่อยที่สุด เข้าถึงแบบลำดับ (sequential) และอ้างด้วย addressแก้ bottleneck ได้ แต่ซับซ้อนกว่า ใช้ใน DSP และ microcontroller
Hybrid: ระดับ L1 cache เป็นแบบ Harvard ส่วน main memory เป็น Von Neumann

BUS

★ เน้นเนื้อหา
  • มี 2 ชนิด: point-to-point กับ multipoint (multipoint เป็นทรัพยากรที่ใช้ร่วมกัน จึงต้องมี protocol ในฮาร์ดแวร์ควบคุม)
  • Data lines ส่งบิตข้อมูล · Address lines บอกตำแหน่งต้นทางหรือปลายทาง · Control lines บอกทิศทางข้อมูลและบอกว่าใครใช้ bus ได้เมื่อไร

★ Bus Arbitration 4 แบบ (master หลายตัวขอใช้ bus พร้อมกัน)

  1. Daisy chain: ส่งสิทธิ์ต่อกันจากตัวที่ priority สูงไปต่ำ
  2. Centralized parallel: ทุกอุปกรณ์ต่อตรงเข้าวงจร arbiter กลาง
  3. Distributed, self-detection: อุปกรณ์ตกลงกันเองว่าใครได้ใช้
  4. Distributed, collision-detection: ใครก็ส่งได้ ถ้าชนกันก็ลองใหม่

Daisy chain นิยมที่สุด แต่อุปกรณ์ priority ต่ำ (I/O) แทบไม่ได้ใช้ bus อาจารย์พูดในคลาส · Point-to-point แยกสายทุกคู่ ง่ายแต่เปลืองสาย · Multipoint ใช้สายร่วม ประหยัดกว่า (เหมือนไฮเวย์กับซอย) แต่ต้องมี protocol
⚠ ข้อหลอก: ตัวที่ตัดสินว่าใครได้ใช้ bus คือ bus arbitrator (arbitration circuit) ไม่ใช่ Control Unit และไม่ใช่ control line

Hardware vs Software approach

★ เน้นเนื้อหา
  • Hardware: เดินสายวงจรให้ทำงานเฉพาะอย่าง ถ้าจะเปลี่ยนงานต้อง rewire
  • Software: ส่งชุดคำสั่ง (codes) เข้าไป ตัว instruction interpreter แปลงเป็น control signal ให้ ALU แบบ general-purpose ทำงาน · เปลี่ยนงานได้แค่เปลี่ยนโปรแกรม
  • ส่วนประกอบหลัก: CPU (interpreter + ALU) และ I/O (รับเข้าและรายงานผล)

Example of Program Execution (ไล่ทีละ step)

★ เน้นคำนวณ

รูปแบบคำสั่ง 16 บิต = opcode 4 บิต + address 12 บิต · 0001=Load AC, 0010=Store AC, 0101=Add to AC

ค่าเริ่มต้น: Mem[940]=0003, Mem[941]=0002 · PC=300 วิธีอ่านคำสั่ง hex 4 หลัก: หลักแรก = opcode ส่วน 3 หลักที่เหลือ = address · 1940 = Load จาก 940 · 5941 = Add ค่าที่ 941 · 2941 = Store ลง 941

Stepเกิดอะไรขึ้น
1Fetch: IR ← Mem[300] = 1940
2Execute “Load 940”: AC ← 0003 แล้ว PC เป็น 301
3Fetch: IR ← 5941
4Execute “Add 941”: AC ← 3+2 = 0005 แล้ว PC เป็น 302
5Fetch: IR ← 2941
6Execute “Store 941”: Mem[941] ← 0005

PC = address ของคำสั่งถัดไป · IR = คำสั่งที่กำลังทำ · AC = ที่เก็บผลชั่วคราว

★ เน้นเนื้อหา

  3. ใส่ address นั้นลง PC แล้วกระโดดไปทำ ISR (Interrupt Service Routine)

Classes of Interrupts

เนื้อหา
  1. Program: overflow, หารด้วย 0, คำสั่งผิด, เข้าถึง memory นอกขอบเขต
  2. Timer: นาฬิกาใน CPU ให้ OS ทำงานเป็นช่วง ๆ
  3. I/O: controller แจ้งว่าทำงานเสร็จหรือมี error
  4. Hardware failure: ไฟดับ หรือ memory parity error

Instruction cycle with interrupts: Fetch → Execute → Interrupt check ถ้ามี interrupt ให้เก็บ context แล้วกระโดดไป handler · interrupt ทำให้ CPU ไม่ต้องรอ I/O (short vs long I/O wait)

  2. 1's: 6 + (−3) แบบ 3 บิต = 110 + 100 = 1|010 → เอา carry ไปบวกกลับที่ LSB (end-around carry) ได้ 011 = 3
  3. Sign & Magnitude โจทย์เสริม ไม่มีในสไลด์: sign เหมือนกันให้บวก magnitude · sign ต่างกันให้เอาตัวใหญ่ลบตัวเล็กแล้วใช้ sign ของตัวใหญ่

Arithmetic & Design Principle 1

★ เน้นเนื้อหา

add a, b, c หมายถึง a ← b + c คือมี 3 operand (2 ต้นทาง + 1 ปลายทาง) ทุกคำสั่งคณิตใช้รูปแบบเดียวกัน
Simplicity favours regularity: รูปแบบเหมือนกันทำให้สร้างง่าย และความเรียบง่ายทำให้เร็วในต้นทุนต่ำ

Memory Operand: A[12] = h + A[8];

★ เน้นคำนวณ

  2. 1 doubleword = 8 bytes ดังนั้น offset = index × 8: A[8] → 64, A[12] → 96 ทำไม ×8: RISC-V นับ address เป็น byte และ 1 ช่องของ array กว้าง 8 byte ดังนั้น A[8] จึงอยู่ห่างจากต้น array 8 × 8 = 64 byte

add  x9, x21, x9   // x9 = h + A[8]

★ เน้นคำนวณ

Principle of Locality

เนื้อหา
  • Temporal: ของที่เพิ่งใช้มีแนวโน้มจะถูกใช้อีกเร็ว ๆ นี้ (เช่นคำสั่งใน loop หรือตัวแปรนับรอบ)

  • วิธีใช้ประโยชน์: เก็บทุกอย่างไว้บน disk แล้ว copy ส่วนที่เพิ่งใช้ (และส่วนใกล้ ๆ) ขึ้นมาไว้ใน DRAM และขึ้นต่อไปที่ SRAM (cache)

  3. CPI จริง = 2 + 2 + 1.44 = 5.44
  4. CPU ที่ cache สมบูรณ์จะเร็วกว่า 5.44/2 = 2.72 เท่า

ทำไมคูณต่างกัน: ทุกคำสั่งต้อง fetch จาก I-cache (100%) แต่มีแค่ load/store 36% ที่ใช้ D-cache · ผลที่ได้คือจำนวน cycle ที่เสียไปกับการรอ memory ต่อคำสั่ง

AMAT ตัวอย่าง: clock 1 ns, hit 1 cycle, penalty 20, miss 5% ได้ 1 + 0.05×20 = 2 ns hit ใช้ 1 cycle เสมอ บวก miss ที่เกิด 5% ซึ่งแต่ละครั้งเสีย 20 cycles เฉลี่ยแล้วจึงได้ 2 cycles ต่อครั้ง · ถ้าลด base CPI หรือเพิ่ม clock rate สัดส่วนเวลาที่ stall รอ memory จะยิ่งมากขึ้น

Multilevel Cache

คำนวณ
  1. L1 อย่างเดียว: base CPI 1, 4 GHz (0.25 ns), miss 2%, memory 100 ns จะได้ penalty = 100/0.25 = 400 cycles และ CPI = 1 + 0.02×400 = 9
  2. เพิ่ม L2 (5 ns ได้ 20 cycles, global miss 0.5%): CPI = 1 + 0.02×20 + 0.005×400 = 3.4
  3. เร็วขึ้น 9/3.4 = 2.6 เท่า

penalty 400 = 100 ns ÷ 0.25 ns ต่อ cycle · พอมี L2 การ miss ใน L1 ส่วนใหญ่เสียแค่ 20 cycles มีแค่ 0.5% (global miss) ที่ต้องไปถึง main memory แล้วเสีย 400

L1 เน้น hit time ต่ำ (เล็กกว่า block ก็เล็กกว่า) ส่วน L2 เน้น miss rate ต่ำ เพื่อเลี่ยงการไปถึง memory

Associativity

★ เน้นคำนวณ
  • Direct mapped: ลงได้ 1 ช่อง ค้นหา 1 tag

  • Fully associative: ลงได้ทุกช่อง ต้องค้นทุก tag (comparator เยอะ แพง)

How much? associativity ยิ่งเพิ่ม miss rate ยิ่งลด แต่ลดได้น้อยลงเรื่อย ๆ (diminishing returns): 1-way 10.3% → 2-way 8.6% → 4-way 8.3% → 8-way 8.1% ตัวเลขคือ miss rate: จาก 1 เป็น 2-way ลดลง 1.7% แต่จาก 4 เป็น 8-way ลดแค่ 0.2% จึงไม่คุ้มที่จะเพิ่มต่อ

Cache Coherence

เนื้อหา
  • ปัญหา: 2 core ใช้ address เดียวกัน ถ้า A เขียน X=1 แต่ cache ของ B ยังเป็น 0 ค่าจะไม่ตรงกัน
  • Coherent คือการอ่านต้องได้ค่าที่เขียนล่าสุด และทุกโปรเซสเซอร์ต้องเห็นลำดับการเขียนเหมือนกัน
  • Snooping: ทุก cache คอยดู bus · Directory-based: บันทึกสถานะการแชร์ไว้ใน directory
  • Invalidating snooping: ก่อนเขียนต้องได้สิทธิ์ exclusive โดย broadcast invalidate ทำให้ cache อื่นเกิด miss ครั้งถัดไปแล้วได้ค่าใหม่ (cache ที่เป็นเจ้าของเป็นตัวส่งค่า)
  • Protocol ช่วยเรื่อง migration (ย้ายข้อมูลไป cache ใกล้ตัว ลด bandwidth) และ replication (สำเนาข้อมูลที่อ่านร่วมกัน ลดการแย่ง)

Memory consistency: การเขียนถือว่าเสร็จเมื่อทุกโปรเซสเซอร์เห็นแล้ว และไม่สลับลำดับการเขียน ดังนั้นถ้า P เขียน X แล้วเขียน Y ใครเห็น Y ใหม่ก็ต้องเห็น X ใหม่ด้วย (สลับลำดับการอ่านได้ แต่สลับการเขียนไม่ได้)

คำนวณ

ตัวอย่าง cache: direct-mapped · write-back · write allocate · block 4 words (16 B) · 16 KB (1024 blocks) · address 32 บิต แบ่งเป็น Tag 18 | Index 10 | Offset 4 · มี valid และ dirty bit · เป็น blocking cache (CPU รอจนเสร็จ) Offset 4 บิต เพราะ block 16 byte = 2⁴ · Index 10 บิต เพราะ 1024 ช่อง = 2¹⁰ · Tag = 32 − 10 − 4 = 18 บิต

  4. Allocate: อ่าน block ใหม่จาก memory แล้วกลับไป Compare Tag

ข้อเสียของ Programmed และ Interrupt I/O: (1) อัตราโอนข้อมูลจำกัดด้วยความเร็วที่ CPU เช็กและบริการอุปกรณ์ได้ (2) CPU ถูกผูกไว้กับการโอนข้อมูล ถ้าข้อมูลเยอะจึงควรใช้ DMA

★ Breakpoints: DMA แทรกได้หลายจุดในรอบคำสั่ง คือก่อน fetch และหลัง fetch, decode, fetch operand, execute เพราะแค่ยืม bus ไม่ต้องเปลี่ยน context ส่วน interrupt แทรกได้จุดเดียวคือหลัง store result (คำสั่งเสร็จแล้ว)

★ DCA (Direct Cache Access): DMA scale ไม่ทันเมื่อ network เร็วมาก (Ethernet 10–100 Gbps, Wi-Fi 3.2–6.76 Gbps) จึงให้ I/O เขียนข้อมูลเข้า cache โดยตรง (ตัวอย่าง: Xeon E5-2600/4600) ถ้าทุก packet ต้องลง main memory ก่อนแล้ว CPU ค่อยอ่าน จะเกิด cache miss ทุกครั้ง ยิ่ง network เร็วก็ยิ่งเป็นคอขวด

DCA strategies: แบบง่ายสุด (Xeon 2006–2010) ใช้กับข้อมูลขาเข้าเท่านั้น ให้ core prefetch packet จาก system buffer · แบบที่ดีกว่าคือ DDIO ที่ข้ามไม่ต้องผ่าน system buffer ใน main memory เลย โดยใช้ last-level cache แทน

Evolution of I/O: (1) CPU คุมอุปกรณ์เอง → (2) มี I/O module แต่ใช้ programmed I/O → (3) เพิ่ม interrupt → (4) DMA → (5) I/O channel มีชุดคำสั่ง I/O ของตัวเอง → (6) I/O processor มี local memory เป็นคอมพิวเตอร์ย่อย · Channel มี 2 แบบ: Selector (อุปกรณ์เร็ว ทีละตัว) และ Multiplexor (อุปกรณ์ช้า หลายตัวสลับกัน)

Pipelining Analogy (ซักผ้า)

★ เน้นคำนวณ
  1. งาน 1 ชิ้นมี 4 ขั้น ใช้ 2 ชม. · ทำ 4 ชิ้นแบบปกติ = 8 ชม.

  3. ถ้าทุก stage สมดุลกัน: เวลาต่อคำสั่ง (pipelined) = เวลาต่อคำสั่ง (non-pipelined) ÷ จำนวน stage · ถ้าไม่สมดุล speedup จะน้อยกว่านี้

เวลารัน n คำสั่งบน pipeline k stage โจทย์เสริม ไม่มีในสไลด์

เวลา = (n + k − 1) × Tc · ตัวอย่าง ld 3 คำสั่ง: single-cycle = 3 × 800 = 2400 ps · pipeline = (3 + 5 − 1) × 200 = 1400 ps คำสั่งแรกใช้ k cycles เต็ม แล้วคำสั่งที่เหลือ n − 1 ตัวเสร็จเพิ่ม cycle ละตัว

⚠ ข้อหลอก: pipeline ใช้ได้ทั้ง RISC (เช่น ARM) และ CISC (เช่น Intel) ไม่ใช่เฉพาะ RISC

Branch Prediction

★ เน้นเนื้อหา

Detecting the Need to Forward

Load-Use Detection & Stall

เนื้อหา
  1. ตรวจตอนคำสั่งที่ใช้ค่าอยู่ที่ ID: ถ้า ID/EX.MemRead = 1 และ ID/EX.RegisterRd = IF/ID.RegisterRs1 หรือ Rs2 แสดงว่าเกิด load-use hazard
  2. Stall: บังคับ control ใน ID/EX ให้เป็น 0 ทำให้ EX, MEM และ WB ทำ nop (เกิด bubble)
  3. ห้ามอัปเดต PC และ IF/ID คำสั่งเดิมจึงถูก decode ใหม่ และคำสั่งถัดไปถูก fetch ใหม่
  4. หลัง stall 1 cycle ค่าจาก MEM ก็ forward ไปที่ EX ได้

Stall ลด performance แต่จำเป็นเพื่อให้ได้ผลถูกต้อง · compiler จัดลำดับคำสั่งเพื่อลด stall ได้ถ้ารู้โครงสร้าง pipeline

Branch Hazard & Reducing Delay

คำนวณ
  1. ถ้ารู้ผล branch ที่ MEM ต้อง flush 3 คำสั่งที่ fetch เข้ามาผิด (ตั้ง control เป็น 0)
  2. ย้าย target address adder และ register comparator มาไว้ที่ ID จะเหลือ flush แค่ 1 คำสั่ง
  3. ตัวอย่าง: 40: beq x1,x3,16 → target = 40 + 16×2 = 72 immediate ของ branch นับเป็นหน่วย 2 byte จึงต้องคูณ 2 ถ้า taken ให้ flush คำสั่งที่ 44 แล้ว fetch ที่ 72

★ เน้นเนื้อหา

  • คำสั่ง: fld.v / fsd.v (load/store vector) · fadd.d.v (บวก vector) · fadd.d.vs (บวก scalar เข้าทุก element)

★ DAXPY (Y = a × X + Y)

Vector vs Scalar / Multimedia ext.

★ เน้นเนื้อหา
  • Vector ช่วยให้เขียนโปรแกรม data-parallel ได้ง่าย ระบุชัดว่าไม่มี loop-carried dependence (ฮาร์ดแวร์จึงเช็กน้อยลง) ได้ประโยชน์จาก interleaved และ burst memory และไม่มี loop จึงไม่มี control hazard
  • ทั่วไปกว่า MMX/SSE และเข้ากับ compiler ได้ดีกว่า
  • เทียบ Multimedia ext.: vector มีความกว้างแปรผันได้ (MMX/SSE กว้างคงที่) และรองรับ strided access (MMX/SSE ไม่รองรับ) · vector unit เป็นทั้ง pipelined และ arrayed (หลาย lane)

★ เน้นเนื้อหา

แบบสลับเมื่อไรข้อดี / ข้อเสีย

สรุปตาราง: GPU มี lane และ thread มากกว่ามาก เพราะเน้นคำนวณขนาน แต่ cache เล็กและ memory น้อยกว่า และไม่มี demand paging หรือ cache coherence เหมือน CPU

Shared vs Distributed memory อาจารย์พูดในคลาส: shared ไม่ต้องทำสำเนาหรือ sync ข้อมูลระหว่างเครื่อง แต่ทุก core รุมใช้ memory ตัวเดียว · distributed (cluster) sync และอัปเดตข้อมูลยาก แต่ขยายได้ ราคาถูก และ availability สูง

Message Passing & Clusters

เนื้อหา
  • แต่ละโปรเซสเซอร์มี private physical address space และสื่อสารด้วยการส่งหรือรับ message
  • Loosely coupled clusters: คอมพิวเตอร์อิสระ แต่ละเครื่องมี memory และ OS ของตัวเอง ต่อกันผ่าน I/O (Ethernet/switch) · เหมาะกับงานอิสระ (web server, database) · availability สูง ขยายได้ และราคาไม่แพง · ปัญหา: ค่าดูแลระบบสูง และ interconnect bandwidth ต่ำ (เมื่อเทียบกับ SMP)
  • Grid computing: คอมพิวเตอร์แยกกันต่อผ่านเครือข่ายระยะไกล (Internet) แจกงานออกไปแล้วรับผลกลับ ใช้เวลาว่างของ PC เช่น SETI@home

Network Topologies

เนื้อหา

Bus · Ring · 2D Mesh · N-cube (เช่น N = 3) · Fully connected · Multistage (crossbar, Omega)
วัดผล: latency ต่อ message, throughput (link bandwidth, total network bandwidth, bisection bandwidth), congestion · ต้นทุน: cost, power, routability on silicon

Multistage networks: Crossbar ต่อโปรเซสเซอร์ทุกตัวถึงกันได้โดยตรงผ่านจุดสวิตช์ (ใช้สวิตช์ P² ตัว เร็วแต่แพง) · Omega network ใช้ switch box 2×2 หลายชั้น ใช้ฮาร์ดแวร์น้อยกว่าแต่เส้นทางอาจชนกัน (blocking)

Benchmarks & Roofline

เนื้อหา
  • Arithmetic intensity = FLOPs ต่อ byte ของ memory ที่เข้าถึง · Attainable GFLOPs/s = min(Peak memory BW × intensity, Peak FP performance) ซึ่งเป็นแนวคิดของ Roofline model
  • ขั้นตอนสร้าง model ของเครื่องหนึ่ง: (1) วัด arithmetic intensity ของ kernel จาก Berkeley Design Patterns (2) หา Peak GFLOPS จาก data sheet (3) หา Peak memory bytes/sec ด้วย Stream benchmark (4) เขียนกราฟ: kernel ที่ intensity ต่ำจะถูกจำกัดด้วย memory bandwidth ส่วนที่ intensity สูงจะถูกจำกัดด้วย peak FP

เนื้อหา
  1. SISD = 1 คำสั่ง 1 ข้อมูล ไม่ใช่หลายคำสั่งพร้อมกัน
  2. Pipeline ใช้ได้ทั้ง RISC และ CISC · ลำดับ Fetch → Decode → Execute → Write back
  3. Exponent: single 8 บิต · double 11 บิต
  4. จุมากสุดในพีระมิด = off-line / magnetic tape (ถูกสุดด้วย)
  5. RAM ชั่วคราว · ROM ถาวร · SRAM เร็วกว่า · DRAM ถูกกว่า
  6. Miss น้อยสุด = fully associative · นิยามสามคำ: write-through, write-back, write-allocate
  7. Daisy chain = ตาม priority · ตัวเลือกว่าใครได้ใช้ bus = bus arbitrator
  8. I/O เร็วสุด = DMA · การ์ดจอต่อเมนบอร์ดผ่าน PCIe
  9. Track = วงแหวน · Sector = ส่วนย่อยของ track · DVD density มากกว่า CD

  14. Cache: ดู index → เทียบ tag → เช็ก valid · block ใหญ่ไม่ได้แปลว่า miss น้อยเสมอ
  15. CPU time = IC × CPI × cycle time · “เร็วกว่า” = ใช้เวลาน้อยกว่า
